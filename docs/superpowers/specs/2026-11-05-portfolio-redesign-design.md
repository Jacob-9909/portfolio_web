# 포트폴리오 리디자인 설계

작성일: 2026-11-05
대상 저장소: `portfolio_web` (Next.js 14 App Router, Tailwind, `output: "export"`, GitHub Pages `/portfolio_web`)

## 1. 왜 바꾸나

지금 페이지(`src/app/page.tsx`, 커밋 `af10f96`)는 eugeneyan.com 같은 문서형으로 만들었다. 흰 바탕, 검은 글자, 링크 파랑만 쓰고, 섹션은 구분선으로 나누며, 다이어그램은 archify가 생성한 SVG에 색을 입힌 것이다. 정돈은 되어 있지만 기억에 남는 장면이 없다. 다이어그램도 생성 도구로 만든 티가 난다. 그 전 버전(Tokyo Night 다크 터미널과 카드 격자, `design/tablefold-figma.html`)도 사용자는 AI가 흔히 내놓는 스타일로 본다.

사용자가 원하는 반응은 두 가지다. 처음 연 사람이 30초 안에 이렇게 느껴야 한다.

1. "이 사람이 AI engineer로서 실제로 이런 걸 만들었구나."
2. "디자인이 뻔하지 않고, AI가 만든 것 같지 않다."

## 2. 목표, 비목표, 실패 조건

**목표**
- 첫 화면은 한 문장으로 이 사람이 일하는 방식을 전한다. 근거는 손을 대면 드러난다.
- 프로젝트 네 개를 길게 스크롤하지 않고 모두 볼 수 있다.
- 다이어그램은 노드 역할이 한눈에 구분되고, 에이전트가 단계별로 일하는 모습을 보여 준다.

**비목표**
- 새 프로젝트나 새 수치를 추가하지 않는다. 내용은 지금 `src/lib/data.ts`에 있는 사실의 범위 안에서만 쓴다.
- 블로그나 글 목록 기능은 만들지 않는다. 내비게이션의 "글"은 기존 블로그 링크로 보내면 된다.

**실패 조건** (기술적으로 돌아가도 이렇게 되면 실패다)
- 사용자가 거절한 패턴이 다시 나온다. 점과 구분선만 있는 레이아웃, 한 가지 색뿐인 글씨, 대문자 kicker, pill 태그, 테두리 카드 격자, 그라디언트, 이모지, 생성기 같은 다이어그램이 여기에 해당한다.
- 컨셉을 덧씌운 장식이 나온다. 사용자가 거절한 시안에는 잡지풍 헤드라인, 타자 애니메이션, 손글씨 폰트와 모눈종이가 있었다.
- 움직임이 손보다 늦다. 커서가 지연되어 따라오거나, 스크롤이 멈춘 뒤에도 전환이 길게 이어지면 안 된다. 사용자는 이걸 "물속에서 움직이는 느낌"이라고 했다.
- 문구가 AI 말투다. 자기를 3인칭으로 소개하는 단정문("정우혁은 ~를 만듭니다")이 대표적인 예다.

## 3. 사용자가 정한 것

### 3.1 전체 톤: Maggie Appleton (maggieappleton.com)
사용자는 이 사이트의 어두운 바탕과 세리프가 만드는 분위기, 그리고 첫 화면의 한 문장 소개 톤을 둘 다 좋다고 했다.

시안에서 확인한 값은 아래와 같다 (`.superpowers/brainstorm/*/content/spike-v4.html`).
- 바탕 `#1b1915` (따뜻한 검정). 글자 `#ede7db`, 본문 `#cfc8ba`, 보조 `#a39b8d`, 흐림 `#5d574d`, 선 `#3a362f`
- 제목: Hahmlet (Google Fonts, 세리프). 본문: Pretendard Variable (지금도 CDN으로 쓰는 중)
- 한국어 줄바꿈: `word-break: keep-all` (지금도 `break-keep` 사용 중)

### 3.2 움직임: Rauno Freiberg (rauno.me)
사용자는 모션그래픽 같은 반응성을 원했다. 다만 시안에서 지연 커서와 0.5~0.9초 전환은 "물속 같다"고 거절했다. 그래서 규칙은 이렇다.
- 입력(스크롤, 클릭, 키, 마우스 올리기)에 즉시 반응한다. 전환은 0.3초 이하로 한다.
- 커스텀 커서는 쓰지 않는다.
- `prefers-reduced-motion`이면 전환을 끈다.

### 3.3 첫 화면
- 큰 세리프 문장: **"틀리면 안 되는 숫자는 LLM한테 맡기지 않습니다."** 사용자가 후보 셋 중에 골랐다. 영어판은 "I don't let LLMs handle numbers that can't be wrong."이다.
- 아랫줄: 이름, 직함, 한 줄 소개. 예시는 "정우혁 · Didim AI Engineer. 은행 폐쇄망과 공장에서 Text-to-SQL 에이전트를 만들어 왔습니다."
- 밑줄 친 말에 마우스를 올리면 포인트 색이 왼쪽에서 차오르고 근거 메모가 뜬다. 시안의 대응은 다음과 같다.
  - "숫자" → 시안에서는 Midas Touch를 근거로 썼다. Midas Touch가 프로젝트 목록에서 빠졌으므로, 남은 프로젝트에서 근거를 가져온다. 문구는 "Text-to-SQL에서 숫자는 LLM이 쓰지 않고 DB 쿼리 결과에서 나옵니다. 범농협 RAG에서는 수치 표를 따로 처리하는 파이프라인을 분리했습니다." 정도로 한다. (내 판단)
  - "은행 폐쇄망" → 마케팅허브: 외부 API 없이 정확도 60%에서 95~100% (팀 성과)
  - "공장" → 선일다이파스: 조회 대기 2~3일에서 30초

### 3.4 프로젝트 배치: 목록 + 고정 무대 (시안 C)
사용자는 3열 격자(A)와 목록 펼치기(B) 대신 이 배치를 골랐다. 고른 이유는 프로젝트를 계속 스크롤하며 보면 "언제 다 내리나" 싶어서다.

**보여 줄 프로젝트는 네 개다** (사용자 확정). 선일다이파스, 농협은행 마케팅허브, 범농협 영업점 어시스턴트, 농협 맛선 상품 추천 에이전트. tablefold, Midas Touch, KoFinSQL은 뺀다.

- 왼쪽: 프로젝트 네 개 목록. 항목마다 이름과 대표 숫자 하나를 붙인다. 지금 고른 항목은 왼쪽 선을 포인트 색으로 표시한다.
- 오른쪽: 고정 무대. 소속과 기간, 한 줄 제목, 다이어그램, 지금 단계의 설명, 단계 막대(예: 3 / 5)가 들어간다.
- 단계는 막대 클릭이나 ← → 키로 넘긴다. 목록은 클릭이나 ↑ ↓ 키로 고른다.
- 페이지 스크롤로 단계가 넘어가지 않는다. 사용자가 C를 고른 이유가 스크롤을 줄이는 것이었다. 시안 v4에서 스크롤로 단계를 넘긴 건 톤과 다이어그램을 보여 주려던 것일 뿐이다. 프로젝트 섹션은 화면 한 칸 높이에 맞추고, 무대는 레이아웃 안에서 제자리에 있다. sticky를 쓰지 않는다. 단계 설명은 스크롤되는 열이 아니라 패널 하나에서 글이 바뀐다. (내 판단)
- 화살표 키는 프로젝트 위젯에 포커스가 있을 때만 동작한다. 목록은 roving tabindex를 쓴다. 그래야 ↑ ↓가 페이지 스크롤을 빼앗지 않는다. (내 판단)
- `stack`은 제목 아래 한 줄로 쓴다. `points`는 단계 설명의 재료가 된다. 남은 네 프로젝트에는 `links`와 `code`가 없다. (내 판단)
- 대표 숫자 (마케팅허브의 "팀 성과" 표기는 빼면 안 된다):

| 프로젝트 | 대표 숫자 | 출처 |
|---|---|---|
| 선일다이파스 | 2~3일 → 30초 | `data.ts` |
| 농협은행 마케팅허브 | 60% → 95~100% (팀 성과) | `data.ts` |
| 범농협 영업점 어시스턴트 | 3,000쪽 | `data.ts` |
| 농협 맛선 | 첫 토큰 응답 20% 단축 | 스토리뱅크 S1 |

### 3.4.1 맛선 프로젝트 내용
`data.ts`에는 "그 밖에 한 일"에 한 줄만 있다. 메인 프로젝트로 올리려면 `~/job/03_스토리뱅크.md`의 S4(맛선)와 S1(ADK 스트리밍)을 근거로 데이터와 다이어그램을 새로 만들어야 한다. 쓸 수 있는 사실은 아래와 같다.
- 농협중앙회 · Didim, 2025.04 ~ 2025.08. Python, Google ADK, LangGraph, React, Vertex AI Search, Google Search
- 한 줄 요약 예시: "쌀과 잡곡을 고객 취향에 맞춰 추천하는 농협 상품몰 에이전트"
- 흐름: '게임하기' 인터랙티브 UI로 가구 형태와 식감 성향을 모은다. 의도 분류 노드(LangGraph)가 질의를 라우팅한다. 12가지 고객 페르소나를 프롬프트에 넣는다. 사내 상품 지식(Vertex AI Search)과 외부 정보(Google Search)를 합친 하이브리드 RAG로 추천하고, React 스트리밍 UI로 답한다.
- 판단 장면: 첫 설계는 모델이 도구를 직접 고르는 Tool Calling이었다. 계속 동작하지 않았고, 응답이 늦고 매번 달랐다. 그래서 LangGraph 의도 분류 노드로 라우팅을 코드로 분리했다. "찰진 저당 잡곡"과 "잘 팔리는 잡곡"처럼 라우팅이 달라야 하는 질의가 오분기되던 문제를 의도 분류의 라우팅 정확도를 지표로 삼아 고쳤다.
- 성능 장면: Google ADK `lite_llm` 내부에서 동기 함수가 이벤트 루프를 막는 지점을 찾아 고쳤다. 첫 토큰 응답이 20% 빨라졌다. 측정 기준은 LLMOps 도구의 노드별 실행 시간이다. 공식 저장소에 이슈를 등록했다.
- **쓰면 안 되는 것**: 라우팅 정확도의 최종 수치(원장에 없음). 등록한 이슈가 공식 반영됐다는 서술(확인 안 됨). 일정 지연을 고객 탓으로 쓰는 것.
- 다이어그램은 `diagrams/matseon.json`을 새로 만들어 위 흐름을 그린다. 되돌림 고리는 없다. (내 판단)

### 3.5 다이어그램
사용자는 역할 구분이 약하다고 했고, 색·모양·아이콘을 "다 합치자"고 했다. v4 시안을 보고는 "괜찮다"고 했다.

| 역할 | 색 | 모양 | 아이콘 |
|---|---|---|---|
| 사람 (질문, 문서) | 모래 `#d9c2a0` | 말풍선 | 사람 |
| 에이전트 로직 | 코랄 `#f0866a` | 둥근 박스 | `<>` |
| 검증 | 민트 `#7fc8b8` | 육각형 | 방패 |
| 응답, 화면 | 블루 `#9db4ff` | 말풍선 (꼬리 반대쪽) | 말풍선 |
| 자원: LLM | 회색 `#a39b8d` | 칩 (위아래 핀) | 칩 |
| 자원: DB, 인덱스 | 회색 | 원통 | DB |

- 노드 위에 역할 이름을 작게 쓴다(사람, 에이전트, 검증, 응답, 자원).
- 단계 상태는 셋이다. 지금 단계는 채우기를 진하게(역할 색 26%) 하고 테두리를 굵게 한다. 지나온 단계는 연하게 칠한다(8%). 남은 단계는 불투명도를 낮춘다(약 0.3).
- 재생성 같은 되돌림 고리는 그 고리를 만든 노드의 역할 색을 쓴다. 고리가 활성화되면 점이 고리를 돌고, 시도 횟수(1/3, 2/3, 통과)를 보여 준다.
- 노드와 엣지의 내용은 지금 `diagrams/*.json`의 노드, 라벨, 보조 라벨, 엣지를 기준으로 한다. 흐름에 이미 들어 있는 시작점(질문)과 끝점(답변, 결과)은 JSON에 없더라도 노드로 더해도 된다. 새 기술 구성 요소는 더하지 않는다. 되돌림 고리는 JSON에 있는 프로젝트(선일다이파스, 마케팅허브)에만 그리고, 나머지는 고리 없이 단계만 밟는다. 맛선은 JSON이 없으므로 3.4.1을 따른다. (내 판단)

### 3.6 남기는 섹션
사용자는 프로젝트 외에 **경력**과 **기술**만 남기라고 했다. 원칙 5개, 타임라인, 그 밖에 한 일(학부, DACON 포함)은 뺀다. 원칙 1번은 첫 화면 문장이 되었고, "재생성 3회 상한" 같은 다른 원칙은 해당 프로젝트의 단계 설명 안에 들어간다.

## 4. 내가 정한 것 (사용자 확인 전)

- **포인트 색은 코랄 `#f0866a`이다.** 시안 v2에서 색 선택기(코랄, 민트, 블루, 핑크, 색 없음)를 보여 줬지만 사용자는 따로 고르지 않았다. 코랄은 에이전트 역할 색과 같은데, 일부러 맞춘 것이다. 에이전트가 이 포트폴리오의 주인공이니 페이지 강조색과 같은 색을 써도 뜻이 통한다. 색은 CSS 변수 하나로 두어 나중에 쉽게 바꿀 수 있게 한다.
- **다크 모드만 둔다.** (사용자 확정) Maggie 톤이 어두운 바탕을 전제로 하기 때문이다. 지금 있는 밝기 토글과 `layout.tsx`의 테마 스크립트는 없앤다. `themeColor`는 `#1b1915` 하나로 둔다.
- **인쇄용 스타일은 밝게 한다.** 인쇄할 때는 흰 바탕과 검은 글자로 바꾸고, 프로젝트는 고정 무대 대신 네 개를 차례로 펼쳐 모든 단계를 정적으로 보여 준다.
- **KO/EN 전환은 유지한다** (`LanguageContext`).
- **모바일(lg 미만)에서는 목록 펼치기(시안 B)로 바뀐다.** 누른 프로젝트만 그 자리에서 열리고, 그 안에서 단계를 넘긴다. 터치 기기에서는 밑줄 메모를 탭해서 연다.
- **경력과 기술은 무대 아래에 짧게 둔다.** 지금의 기간–내용 2열 형식을 새 톤에 맞춰 다시 스타일한다.
- **연락처**(이메일, 블로그, GitHub, PDF)는 상단 내비게이션과 푸터에 둔다.

## 5. 제약

- 정적 export와 `basePath: "/portfolio_web"`를 유지한다. GitHub Pages 워크플로(`.github/workflows/static.yml`)가 `npm run build` 후 `out/`을 배포한다.
- 새 의존성은 꼭 필요할 때만 추가한다. 모션은 CSS 전환과 소량의 JS로 충분하다.
- 수치, 기간, 고유명사의 원장은 `~/job/02_핵심-스펙.md`와 `03_스토리뱅크.md`이다 (`data.ts` 첫 줄 주석). 문구를 새로 쓸 때도 이 범위를 넘으면 안 된다.
- 접근성: 키보드만으로 프로젝트와 단계를 다 볼 수 있어야 한다. 다이어그램에는 텍스트 대체가 있어야 하고, 대비는 WCAG AA를 맞춘다.

## 6. 빌더에게 맡기는 것

- **단계 나누기와 단계별 문구.** 프로젝트마다 몇 단계로 나눌지, 단계마다 어떤 노드를 켤지 정한다. 근거는 `diagrams/*.json`의 흐름과 `data.ts`의 `points`다. 선일다이파스는 시안의 5단계가 기준이다. 문구 규칙은 이렇다.
  - 합니다체로 쓴다. 자기 3인칭 소개, 거창한 단정, 같은 어미 반복을 피한다.
  - 구체 명사와 숫자를 쓴다.
  - 예시 질문처럼 지어낸 내용은 "예시"라고 표시한다.
  - 사용자가 최종 문구를 검토한다.
- **다이어그램 렌더링 방식.** archify 파이프라인(`diagrams/build.py`, `src/lib/diagrams.ts`)을 대체하는 방법을 정한다. JSON을 읽는 React SVG 컴포넌트를 만들지, 프로젝트별 SVG를 손으로 짤지 고르면 된다. 3.5의 시각 규칙과 단계 상태만 지키면 된다. archify 타입은 이렇게 대응시킨다: `external` → 사람, `backend` → 에이전트, `security` → 검증, `frontend` → 응답, `cloud` → LLM, `database` → DB. `messagebus`(도구, 외부 API)는 자원 계열 안에서 구분되는 모양을 하나 정한다.
- **레이아웃 세부.** 간격, 반응형 분기점, 무대 크기, 단계 막대의 생김새.
- **기존 파일 정리.** `css/`, `scss/`, `fonts/`, `js/`, `index.html`, `single.html` 같은 옛 정적 사이트 잔재를 지울지 판단한다. 지금 Next 빌드에서는 쓰지 않는 것으로 보인다.
