기준 브랜치: `feat/sticky-nav` (PR #2, 상단 고정 내비·여백 축소·다이어그램 확대. 아직 merge 전). 이 작업은 그 위에 `redesign/linear` 브랜치로 쌓는다.

## 1. 왜 다시 바꾸나

1차 리디자인을 배포한 뒤 사용자가 전체를 다시 보고 "무난하다"고 했다. 구체적인 불만은 세 가지다.

1. 배경이 한 가지 색이라 단정하기만 하다.
2. 섹션끼리 구분감이 없다.
3. 처음 봤을 때 눈에 확 들어오는 게 없다.

첫 3초 안에 와닿아야 하는 것은 사용자 말로 **"아, 얘는 뭐 하는 사람이구나!"**다. 그리고 그 사람은 Text-to-SQL만 하는 게 아니다. 사용자가 직접 짚었다. "단순히 t2s agent만 있는 게 아니라 챗봇도 하고 추천 에이전트도 하고 그랬는데." 그러니까 첫 화면은 여러 종류의 에이전트를 만드는 사람으로 보여야 한다.

## 2. 목표, 비목표, 실패 조건

**목표**
- 첫 화면에서 실제 앱처럼 생긴 창이 네 프로젝트의 결과 화면을 보여 준다. Text-to-SQL 두 개, RAG 챗봇, 추천 에이전트다. 보는 사람이 "이런 걸 만드는 사람"이라고 바로 안다.
- 섹션마다 경계가 분명하다. 배경 띠, 번호 배지, 테두리 카드로 나눈다.
- 화면 안의 내용은 칸(카드)으로 묶이고, 역할 색 배지·굵기·색으로 위계가 보인다. 사용자 말: "안에 바운더리를 만들어서 구분감을 조금 더", "색도 어둡고 그러니까 잘 구분이 안 되는 느낌", "볼드체나 색 구분을 통해서".

**비목표**
- 새 프로젝트, 새 성과 수치를 만들지 않는다. 프로젝트의 사실(기간, 스택, 대표 숫자, 단계 설명)은 지금 `src/lib/data.ts`, `src/lib/flows.ts`의 값을 그대로 쓴다.
- 블로그·글 목록 기능은 만들지 않는다.

**실패 조건**
- 첫 화면이 Text-to-SQL 하나만 하는 사람처럼 보인다.
- 창 안에서 누를 수 없는 것이 누를 수 있게 생겼다. 사용자가 원래 사이드바 메뉴를 보고 "지금 내가 눌러야 할 것 같이 생겼어"라고 했다. 실제로 누를 수 있는 것은 탭뿐이어야 한다.
- 탭이 저절로 넘어간다. 사용자가 "전환 속도가 너무 빠른 것 같아, 굳이 그거 안 줘도 될듯"이라고 했다.
- 샘플 내용이 실제 고객 데이터처럼 보인다. 샘플이라는 표시가 늘 보여야 한다.
- 자기를 3인칭으로 소개하는 AI 말투 문구("정우혁은 ~를 만듭니다")가 다시 나온다. (1차 설계의 실패 조건을 그대로 이어받는다)
- 움직임이 손보다 늦다. (1차 설계와 같다)

**1차 설계에서 바뀌는 것.** 1차 설계 §2는 "pill 태그"와 "테두리 카드 격자"를 거절한 패턴으로 적었다. 이번에 사용자는 pill 탭·역할 배지·테두리 카드가 들어간 시안을 보고 승인했다. 그러니 이 둘은 이제 실패 조건이 아니다. 그라디언트는 시안에 있는 범위(앱 창 위쪽의 아주 옅은 빛, 현재 경력 카드 위쪽의 옅은 색)까지만 허용한다.

## 3. 사용자가 정한 것

### 3.1 방향: Linear (linear.app)
레퍼런스 8곳(Dennis Snellenberg, Linear, Brittany Chiang, Anthropic, Stripe Press, Rauno, Lynn Fisher, Maggie Appleton)을 실제 화면으로 보여 줬고, 사용자는 Linear를 골랐다("linear가 약간 멋있어 보이는데"). 그전에 내가 머리로 만든 첫 화면 시안 세 개(숫자 크게, 작업 장면, 한 문장 형광펜)는 모두 거절했다("와 다 별로야").

Linear에서 가져온 것:
- 차가운 검정 바탕과 흰 글씨·회색 글씨의 위계. 큰 문장의 앞부분은 흰색, 뒷부분은 회색으로 쓰는 방식.
- 첫 화면 문장 바로 아래에 실제 제품 화면을 크게 까는 방식.
- 고객사 이름을 한 줄로 늘어놓는 띠.
- 번호 붙은 선 그림(FIG 0.1~0.3).
- 섹션마다 큰 제목과 큰 패널.

### 3.2 첫 화면
위에서 아래로:
1. 고정 내비 (PR #2 그대로). 시안처럼 오른쪽 끝에 흰 알약 모양 "연락하기" 버튼을 더한다.
2. 큰 문장: "틀리면 안 되는 숫자는 LLM한테 맡기지 않습니다." (1차에서 사용자가 고른 문장 그대로)
3. 소개 한 줄: "디딤 AI Engineer 정우혁. 은행, 공장, 농협 상품몰에서 Text-to-SQL·RAG 챗봇·추천 에이전트를 만들어 왔습니다." 오른쪽에 "포트폴리오 PDF →".
4. **앱 창** (아래 3.3)
5. 함께 일한 곳 띠: 선일다이파스 · NH농협은행 · 농협중앙회 · 삼일PwC · 삼정KPMG · Google. 아래에 "함께 일한 곳" 캡션. (뒤의 셋은 범농협 프로젝트 협업사로 `data.ts`에 이미 있다)

### 3.3 앱 창
- 위쪽 탭 4개: ERP 질의 (Text-to-SQL) · 마케팅 질의 (Text-to-SQL) · 규정 챗봇 (RAG) · 쌀·잡곡 추천 (Agent). **누를 때만 바뀐다. 자동 전환 없음, 진행 막대 없음.**
- 탭 줄 오른쪽 끝에 "샘플 화면 · 예시 데이터" 알약을 늘 보이게 둔다.
- 창은 세 칸이다.
  - **왼쪽: 프로젝트 정보.** 메뉴처럼 보이면 안 된다(하이라이트·hover 없음). "프로젝트 정보" 작은 제목, 프로젝트 이름, 그 아래 고객·기간·환경·스택(또는 협업·기간·스택), 맨 아래 대표 숫자(코랄, 굵게). 값은 `data.ts`의 것.
  - **가운데: 결과 화면.** 질문 말풍선(베이지 테두리, "현업 질문"·"창구 직원"·"고객" 배지, 핵심어 굵게) 아래로 단계 카드가 쌓인다. 카드는 왼쪽 3px 역할 색 띠, 맨 위 줄 "역할 배지 + 굵은 제목 + 회색 설명"이다.
  - **오른쪽: 실행 기록.** 관련 항목끼리 묶은 테두리 칸. 값은 굵은 흰색, 통과는 청록, 실패는 코랄, 핵심 숫자(30초, 20% 단축 등)는 크게.
- 역할 색은 1차 다이어그램과 같다: 사람 베이지, 에이전트 코랄, 검증 청록, 응답 파랑.
- 글씨는 창 안에서도 13~15px 이상. 사용자가 "글씨 크기도 좀 키워놔도 될 것 같아"라고 했다.
- 내용은 샘플이고, 사용자가 지어내도 된다고 했다("어차피 샘플이니까"). 탭별 내용은 시안 그대로 쓴다.
  - ERP 질의: CTE 2개, `RANK() OVER`, `NULLIF`, `LEFT JOIN`이 들어간 MSSQL 쿼리 → 사전 검증 통과 → 4행 결과표(달성률이 계획 이상이면 청록, 미만이면 코랄).
  - 마케팅 질의: 1회차가 없는 컬럼(`branch.region`)으로 실패 → 오류를 넣어 재생성 → 2회차 통과. 고쳐진 `region_nm`에 청록 형광. 답변 문장 + 3행 표.
  - 규정 챗봇: 비조합원 예탁금 질문. 답변은 번호 붙은 칸 3개(비과세, 우대금리, 창구 안내)와 칸마다 근거 칩. 근거 문서 4건 카드, 이어서 물어볼 질문 2개.
  - 쌀·잡곡 추천: "2인 가구, 찰진 밥, 섞어 먹을 잡곡" 질문 → 의도 분류(취향 기반, "잘 팔리는 잡곡"과 다른 경로) → 페르소나 → 상품 카드 4개 → 스트리밍처럼 커서가 깜빡이는 답변.
- 쌀 상품은 실제 농협 상품 이름을 쓴다(김화농협 철원오대쌀 10kg, 정읍시농협 신동진 10kg, 국산 찰현미, 국산 찰오곡). 사진은 쓰지 않고 쌀 포대 그림을 SVG로 그린다. 사용자가 "농협에서 쌀 상품 조회해서 그거 기반으로 이미지 만들어서"라고 했다.
- 샘플이 넘지 말아야 할 선: 프로젝트 쪽 사실(대표 숫자, 기간, 스택, 기술 이름, 1회차 실패 후 재생성 상한 3회, 첫 토큰 20% 단축)은 실제 값만 쓴다. 지어내도 되는 것은 질문, 쿼리, 표의 수치, 규정 내용, 쪽수, 상품 설명 같은 화면 속 데이터다. 1차 설계 §3.4.1의 "쓰면 안 되는 것"(맛선 라우팅 정확도 최종 수치, 이슈 공식 반영 서술 등)은 샘플에도 넣지 않는다.

### 3.4 아래 섹션
섹션은 배경을 번갈아 깐 띠(`#08090a` / `#0d0e10`)와 위쪽 가는 경계선으로 나눈다. 섹션 위에 코랄 번호 배지(01~04)와 섹션 이름을 붙인다. 위아래 여백은 84px 안팎. (PR #2에서 사용자가 여백이 많다고 했다)

- **01 일하는 방식.** 큰 문장 "SQL을 쓰든, 규정을 찾든, 상품을 고르든 같은 원칙으로 만듭니다. (회색) LLM에게는 말을 맡기고, 숫자와 근거와 분기는 코드가 책임집니다." 아래 카드 3장: 위쪽 역할 색 띠, 유형 배지, FIG 번호, 등각 선 그림, 굵은 제목, 설명(핵심어 굵게), 맨 아래 해당 프로젝트 이름.
  - FIG 0.1 Text-to-SQL "숫자는 DB가 계산" (막대 그림) · 선일다이파스 · 마케팅허브
  - FIG 0.2 RAG 챗봇 "답에는 근거를 붙인다" (문서 더미에서 한 장 빠진 그림) · 범농협 영업점
  - FIG 0.3 추천 에이전트 "분기는 코드가 정한다" (갈림길 그림) · 농협 맛선
- **02 프로젝트 · 어떻게 돌아가나.** 위에 프로젝트 탭 4개(알약, 유형 이름 함께). 앱 창이 "무엇이 나오나"라면 여기는 "구조"다.
  - 왼쪽: 한 줄 소개(`headline`), 숫자 카드(첫 카드 코랄), 기간·환경·스택.
  - 오른쪽: 다이어그램 카드. 범례, 다이어그램, 그 아래 단계 카드 줄. 현재 단계 카드는 강조한다.
- **03 경력.** 카드 3장. 현재(Didim) 카드만 코랄 테두리·"현재" 배지·조금 더 넓게.
- **04 기술.** 분야별 카드와 칩. 배치는 세 줄이다. 사용자가 "기술 쪽 칸 여백 조정 잘 해주고"라고 해서, 칸 안에 빈 공간이 남지 않게 맞췄다.
  - 첫 줄: AI 카드(두 칸 너비, 코랄 테두리, 아이콘 4열 × 2줄) + 언어 카드(아이콘 세로 목록). 두 카드는 같은 높이로 늘어나고, 안의 칩이 그 높이를 고르게 나눠 채운다.
  - 둘째 줄: 백엔드·데이터, 인프라, 도구 카드 세 장.
  - 셋째 줄: 자격 카드가 한 줄 전체.
  - 칩마다 아이콘을 붙인다. 사용자가 "너무 단정하다", "각 기능에 맞는 아이콘 같은 걸 넣으면 좋을 것 같은데, 나 깃허브 readme에 있는 것처럼"이라고 했다. 사용자 GitHub 프로필 README(`Jacob-9909/Jacob-9909`)는 skillicons.dev 타일과 자체 로고(`assets/langgraph-logo.svg`, `langchain-logo.svg`, `mcp-logo.svg`, `google_adk.png`)를 쓴다.
  - 모양: 어두운 둥근 사각 타일(skillicons 바탕색 `#242938`) 안에 로고. 일반 칩은 24px, AI 카드는 38px, 언어 카드는 30px 타일.
  - 출처 순서: skillicons.dev에 있으면 그것, 없으면 Simple Icons 글리프를 같은 타일에 얹고, 둘 다 없으면 글자 타일(예: Oracle "ORA", MSSQL "MS", PgVector "pgv", Opik "Op", Tableau "T", Codex "Cx", Kiro "K"). RAG·Fine-tuning·SQL은 로고가 없으니 선 그림 타일(돋보기 문서, 슬라이더, 원통).
  - 아이콘 파일은 빌드 때 외부에서 불러오지 않고 `public/icons/`에 넣어 둔다(정적 배포, 폐쇄망에서 열어도 깨지지 않게).
  - 자격 칩은 아이콘 대신 청록 체크 표시.
- 푸터: 이름·직함, 이메일·GitHub·블로그·포트폴리오 PDF.

### 3.5 유지하는 것
- 어두운 테마만. KO/EN 전환(상태 유지 포함). 프로젝트 4개. 경력·기술만 남기는 구성. 고정 내비.

## 4. 내가 정한 것 (사용자 확인 전)

1. **색은 차가운 검정으로 바꾼다.** 시안 값: 바탕 `#08090a`, 띠 `#0d0e10`, 카드 `#111215`~`#17181c`, 글자 `#f7f8f8`, 본문 `#d0d6e0`, 보조 `#8a8f98`/`#9ba1ab`, 흐림 `#62666d`, 선 `#23252a`~`#2b2d33`. 역할 색과 코랄은 그대로.
2. **글꼴은 Pretendard 하나로 간다.** 시안이 전부 고딕이었고 사용자가 그걸 승인했다. Hahmlet은 뺀다. 숫자·코드·FIG 라벨은 시스템 고정폭.
3. **첫 화면 문장의 근거 메모(밑줄 문구)는 남긴다.** 시안에는 없지만 1차에서 만든 기능이고 해가 없다. 모양만 새 색에 맞춘다.
4. **영어판도 만든다.** 앱 창 샘플, 원칙 카드, 섹션 이름까지 모두 EN을 둔다. 지금 사이트가 KO/EN을 지원하기 때문이다.
5. **모바일(lg 미만).** 앱 창은 탭 줄(가로 스크롤)과 가운데 결과 카드만 보여 준다. 프로젝트 정보는 카드들 위에 한 줄 요약(이름 · 대표 숫자)으로 줄이고, 실행 기록 칸은 숨긴다. 원칙·경력·기술 카드는 한 줄에 하나씩 쌓는다. 프로젝트 섹션은 지금처럼 목록 펼침 방식.
6. **앱 창의 창 높이는 내용에 맞춘다.** 시안은 고정 높이와 아래쪽 흐려짐을 썼지만, 탭마다 내용 길이가 달라 실제로는 탭 중 가장 긴 내용에 맞춘 고정 높이(데스크톱)로 해서 탭을 바꿔도 아래 내용이 튀지 않게 한다.
7. **프로젝트 섹션 다이어그램은 지금 `FlowDiagram`을 다시 쓴다.** 도형·좌표 데이터(`flows.ts`, `geometry.ts`)는 그대로 두고 색과 채움만 시안처럼 바꾼다(노드 안쪽은 역할 색이 아주 옅게 섞인 어두운 채움, 라벨 흰색). 단계별로 켜지는 동작, 재생성 고리 애니메이션도 그대로. 시안의 단계 카드 줄은 실제 단계 수(4~5개)만큼 나오고, 누르면 그 단계로 간다(지금의 단계 막대를 대신한다).
8. **인쇄.** 앱 창은 인쇄에서 숨기고, 지금처럼 프로젝트 네 개와 모든 단계를 흰 바탕에 펼친다.
9. **샘플 데이터는 코드 한 곳에 모은다** (예: `src/lib/samples.ts`). 실제 사실(`data.ts`)과 섞이지 않게 하려는 것이다.
10. **앱 창 안에서 무엇이 사실이고 무엇이 샘플인가.** 사실(실제 값만): 왼쪽 프로젝트 정보 전부, 오른쪽 실행 기록 중 30초 · 재생성 상한 3회 · 사내 vLLM · 외부 API 없음 · 규정집 3,000쪽 · 페르소나 12개 · Vertex AI Search/Google Search · 첫 토큰 20% 단축, 쌀 상품 이름. 나머지(질문, 쿼리, 표 수치, "테이블 412개 중 3개", "후보 12건 → 4건", "근거 없는 문장 0", 규정 내용과 쪽수, 상품 설명)는 샘플이다. 샘플 표시 알약이 늘 보이므로 이것으로 충분하다고 본다.
11. **`data.ts`에 칸을 나눠 넣는다.** 프로젝트마다 `client`, `period`, `env`, `stack`, `metrics[]`(값과 이름)를 둔다. 새 사실은 만들지 않는다. 값은 지금 `meta`, `number`, `stack`과 `flows.ts`의 단계 문구에 이미 있는 것에서만 가져온다(선일다이파스 120명 · 월 600회, 범농협 약 60개 · 3,000쪽, 마케팅허브 20명 · 월 200회 등). 숫자가 세 개보다 적은 프로젝트는 있는 만큼만 카드를 보여 준다.
12. **소개 한 줄의 근거 메모.** 문구가 바뀌어 "은행 폐쇄망"이 없어지므로 메모를 "은행"(마케팅허브 60% → 95~100%, 팀 성과), "공장"(선일다이파스 30초), "농협 상품몰"(맛선 추천 에이전트, 첫 토큰 20% 단축)에 단다. 메모 문구는 지금 메모와 `data.ts`의 사실 범위 안에서 쓴다.
